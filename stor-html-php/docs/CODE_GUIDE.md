# شرح تنظيم الكود

## HTML

كل ملف داخل public هو صفحة مستقلة لها head وtitle وviewport وheader وmain وfooter. لا يوجد app/views/store.php ولا ملفات PHP من ثلاثة أسطر تعرض جميع الواجهات. كل صفحة تحمل محتواها الخاص في main. template الصغير داخل بعض الصفحات مكوّن متكرر فقط مثل بطاقة المنتج أو بند السلة، ولا يحتوي صفحات الموقع الأخرى.

عند تحديث البيانات يعيد store.js استعمال نسخة من HTML الصفحة الحالية في الذاكرة. هذه النسخة مأخوذة من نفس الملف الذي فتحه المستخدم، ولا يبني JavaScript الصفحة من سلاسل HTML ولا يحمّل واجهات أخرى بدل الانتقال بين الملفات.

## CSS

- style.css: تصميم STOR الأصلي والترويسة والمنتجات والنماذج والاستجابة.
- admin.css: لوحة الإدارة والجداول وتحرير المنتجات.
- course.css: صفحات المعلومات والمعرض والجداول وعرض الشرائح.
- setup.css: معالج أول تشغيل فقط.

يوجد مثال inline واحد متعمد في about.html لأن ملف المقرر يطلب نوعين من CSS؛ جميع قواعد التصميم الأخرى خارج HTML.

## JavaScript

- store.js: بيانات الصفحة الحالية، اللون بالـCanvas، المقاسات، السلة، الحسابات والطلبات. ينقل الروابط إلى ملفات HTML فعلية.
- api.js: fetch إلى PHP، وحفظ CSRF في الذاكرة. لا كلمات مرور في localStorage.
- admin.js: إضافة/تعديل/حذف المنتجات، الحالات والفواتير، وتجديد جدول PHP مع الحفاظ على حقل البحث.
- validation.js: الحقول المطلوبة والبريد قبل إرسال النموذج.
- slideshow.js: عرض الشرائح وأزراره وإيقافه واحترام تقليل الحركة.

## PHP / MySQL

app/bootstrap.php يقرأ ملفًا خاصًا خارج public، ويستخدم PDO prepared statements، والجلسات وCSRF. auth.php للحسابات وArgon2id ورموز الاستعادة أحادية الاستخدام. catalog.php لإدارة المنتجات مع version لمنع استبدال تعديل أحدث. orders.php يحسب السعر من DB ويخصم المخزون ضمن معاملة ويحمي من تكرار checkoutKey. mail.php يشفر محتوى طابور البريد ثم يرسله بـPHPMailer وTLS ويمسحه بعد النجاح.

public/dashboard.php يعرض الإدارة، وapp/dashboard-table.php ينفذ عرض المنتجات والبحث من MySQL مباشرة. الإضافة والتعديل والحذف من أزرار الإدارة تُرسل إلى public/api.php، ولا يكفي إخفاء الأزرار لحماية الصلاحيات؛ الخادم يتحقق من دور الجلسة.

23 جدولًا تشمل schema_migrations و3 views. جدول products يبدأ بـ15 منتجًا. قاعدة واحدة مشتركة بين العميل والأدمن تحفظ ترابط الطلبات والمخزون والفواتير، والأدوار منفصلة بالصلاحيات داخل PHP.

## حدود النسخة

الدفع عند الاستلام نموذج تعليمي؛ لا بوابة دفع أو تكامل شركة شحن حقيقي. اختيار اللون معاينة تقريبية، والمخزون للمنتج/المقاس. رسائل SMTP تحتاج إعداد البريد وجدولة عامل الرسائل على جهاز المالك أو استضافته. لا تنقل بيانات دخول Aiven أو الموقع القديم إلى هذه الحزمة تلقائيًا.
